# 最终验收门槛

此文档是待执行标准，**不是验收结果**。当前工程包所有应用用例初始状态为 NOT_RUN。

## 进入条件
实现覆盖全部 [P0 需求](../requirements/catalog.md)；应用 README 有真实安装与运行命令；lockfile 已保存；测试/生产时钟隔离；fixture 可导入；没有临时假数据路径、不可用入口和 debug 后门。

## 必须全部通过的 Gate
| Gate | 通过标准 | 证据 |
|---|---|---|
| G01 功能 | 全部 P0 对应 AC 用例 PASS；主训练闭环、取消与错误分支可复现 | 追踪矩阵、E2E 日志 |
| G02 数据 | 持久化、恢复、原子完成、导入导出、quota、坏数据、跨标签冲突通过 | 领域/存储测试及浏览器证据 |
| G03 工程 | 全新安装、lint、typecheck、unit、component、E2E、build 全部退出 0 | 实际命令/退出码/版本 |
| G04 视觉 | 桌面与手机截图齐全；视觉评分 ≥9/10，无 0 分项；英文/白色/扁平一致 | 截图索引与评审记录 |
| G05 无障碍 | 自动检查无 serious/critical 违规，键盘主链与读屏抽查通过，对比度/回流通过 | 工具输出、手动记录 |
| G06 性能与兼容 | 满足性能预算；Chromium + 至少一个第二引擎主链通过 | 测量记录、浏览器版本 |
| G07 交付 | README、证据、已知限制、最终报告完整，代码与锁文件一致 | 交付清单 |

P0 不允许用多数通过替代全部通过。所有 Gate 均 PASS 才可写最终结论 PASS。环境或工具缺失 → BLOCKED；已确认实现未完成或有缺陷 → FAIL/PARTIAL。任何 NOT_RUN 都不能支持最终 PASS。

## 严重级别
- S0：数据泄露、输入执行、跨用户访问（生产扩展）等严重问题，立即阻断。
- S1：数据丢失、重复完成、无法记录/恢复/导入、核心统计错误、无法启动，阻断。
- S2：P0 功能局部不符、手机关键操作不可达、键盘受阻、视觉门槛未满足，阻断。
- S3：不影响需求与门槛的文字微调或装饰建议，可留有明确记录；不能用 S3 掩盖 P0 未通过。

所有未关闭 S0/S1/S2 都阻断 PASS。缺陷即使有绕路操作，仍按其需求影响判断，不能仅因“手动能绕过”降低级别。

## 验收执行顺序
1. 冻结候选代码版本与 lockfile，记录环境。
2. 全新安装与静态/领域/组件检查。
3. 用固定 fixture 执行主链及错误/日历/单位/并发测试。
4. 获取所有页面与状态截图，执行视觉与无障碍检查。
5. 性能、第二引擎、生产预览与深链接检查。
6. 填写逐项检查、缺陷清单和 [最终报告](../../templates/final-report.md)。

候选版本改动后，旧证据需注明对应版本，重跑受影响检查；跨领域变更至少重跑核心主链。禁止把旧版本截图与新版本日志混合而不说明。
