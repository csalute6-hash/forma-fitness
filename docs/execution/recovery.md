# 失败、阻塞与恢复

## 构建 / 类型失败
保存真实日志，定位首个根因；使用项目锁定依赖；不靠关闭 strict 或跳过 build 规避。环境缺少运行时或依赖下载失败时写 BLOCKED，说明已完成的静态工作与下次可执行命令。

## 功能失败
创建缺陷：需求 ID、前置数据、步骤、实际/预期、环境、证据、严重级别。修复先确认失败能复现；回归覆盖直接路径及同一领域共享调用。数据丢失优先于视觉打磨。

## 存储损坏
不要自动 reset。进入恢复界面，保留原始值；提供下载备份、重试和明确确认的重置。读取权限失败时不宣称备份成功；提示用户浏览器环境限制。恢复流程本身必须测试。

## 测试偶发失败
区分等待条件、时间依赖和实际竞态。改用可观察状态和注入时钟，不加大段任意 sleep。保留第一次失败记录及最终修复证据；不靠无限重跑掩盖不稳定。

## 中断续作
读取 progress 最新记录 → 检查工作区差异 → 确认正在进行的任务 → 运行最小检查 → 继续。不要重写整仓库；不擅自删除用户文件。

## 无法完成时
最终报告 PARTIAL 或 BLOCKED，列出哪些 P0 未通过、具体原因、恢复条件与下一步。没有实测不得填 PASS。截图工具不可用时标明视觉验证阻塞；静态阅读不代替视觉验收。
