# 计算、单位与时间

## Canonical 数值
内部重量全部为 kg，身高（若未来使用）为 cm。P0 不收集身高；保留 cm/in 偏好仅作为单位对设置，不增加身高表单。kg→lb 乘 2.2046226218，in→cm 乘 2.54。内部转换保留精度，不将展示舍入结果写回历史。数字必须有限，禁止 NaN、Infinity、空字符串当作 0。

训练外部负重：0–500 kg（展示为 lb 时按同一 canonical 上限验证）；次数 1–100 的整数；组数每动作 1–20（编辑中的 0 组允许但不可完成）；动作每场最多 30；休息 15–600 秒整数。体重 20–350 kg，日期为用户本地今天或过去。计划目标重量允许 0，目标次数 1–100，目标组数 1–20。文本去除首尾空白；训练/计划标题 1–60 字符，描述或备注最多 500 字符。

输入接受当前展示单位最多 2 位小数；kg 显示最多 2 位，lb 最多 2 位；表格保留需要的精度不强制 .00。汇总容量显示到整数（四舍五入），但原始加总不先逐组舍入；格式使用 en-US。使用 numeric inputMode 并在提交层独立校验；正负号、指数形式、逗号等未支持形式应给出清楚错误。

## 容量与纪录
- 一组容量 = 外部重量 kg × reps。自重动作的 0 kg 不代表身体重量，因此容量为 0；动作次数仍记录。UI 用 External load 说明。
- 一次训练容量 = 所有已完成组容量之和。
- 最高重量纪录 = 某动作完成组的最大 kg；并列选最近 completedAt，再按 workout ID 字典序确定。
- 最大单组容量纪录 = max(weightKg × reps)，同值同样规则。
- 只有 completed history 参与统计，active 草稿与已放弃训练不参与。
- 删除历史后从剩余数据重新派生，不保存另一个可漂移的 PR 表。

## 时间与周
时间戳存 ISO 8601 UTC，体重日期和训练完成日期使用 `YYYY-MM-DD` 本地日历日期。每场完成时存 `completedLocalDate` 和 IANA `timeZone`；日历分组以该不可变本地完成日期为准，避免用户旅行后历史跳日。开始与结束 timestamp 用于时长计算。禁止把 UTC 日期截断当本地日期。

本周：测试/运行当前本地日期所在周，周一至周日，含两端；查询以 day key 比较，不以固定 7×24 小时模拟自然周。最近 7 天：今天及前 6 个本地日，最近 30 天同理。未来日期不进入当前窗口。Dashboard 只显示当前周；Progress 展示当前周加前 7 周。

训练时长 = floor((completedAt-startedAt)/1000)，最少 0；活跃时长用 now-startedAt。P0 没有暂停训练。跨午夜训练计入完成日所在周。系统时钟倒退导致完成时间早于开始时拒绝完成，提示检查系统时间；超过 24 小时仍允许恢复与完成，但摘要提示 “This workout has been running for over 24 hours.” 并允许放弃。显示时长使用 `45m`、`1h 05m`；明细秒数可保留。

完成次数 = 窗口内 history 数量；周完成率 = min(100, count/weeklyGoal×100)，文字仍显示真实次数，例如 5 / 3。Training time = 窗口内时长总和。历史排序 completedAt 降序，同时间按 id 升序。训练次数趋势按 completedLocalDate 所在周分桶；容量转换在最终展示时进行。
