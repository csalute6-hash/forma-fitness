# 代码与依赖规则

- 先使用现有工程，再选择新依赖。新依赖说明目的、体积影响与替代方案；锁定版本并提交 lockfile。不并行引入两套路由或两套表单体系。
- 领域函数保持纯函数，日期和 ID 来源注入，避免随机性污染测试。页面只组合领域命令，不复制统计公式。
- TypeScript 使用 strict；输入边界从 unknown 校验后收窄，禁止用 `as AppData` 假装完成导入验证。
- 不使用全局 DOM 查询和手动改 DOM 绕过状态系统；不得使用不受控 HTML 渲染用户内容。
- 金额、热量等不在范围内的占位字段直接移除。用户数值禁止随机生成或来自与记录无关的常量。
- 组件命名表达职责；模块内部实现可小而直接，避免提前建设插件平台或通用状态引擎。
- 重复三次的计算或样式应合并到共享边界；不要为单行 UI 创建无意义抽象。
- 格式化与 lint 规则统一；不得通过全局 disable、跳过类型检查、注释掉断言让检查通过。
- 加载失败可恢复，错误码可测试；禁止 catch 后返回空数组让损坏数据伪装成空状态。
- 项目 README 中记录真实可运行命令；没有运行的命令不写“通过”。

代码审查优先顺序：数据丢失 / 统计错误 / 训练阻断 → 键盘与手机可用性 → 一致性与性能 → 装饰性细节。所有引入的临时调试入口、console 私人数据和硬编码测试时钟在交付前移除或只在测试环境隔离。
