# 性能与兼容验证

这是项目验收预算，不是已测指标。所有结果需注明设备、系统、浏览器版本、构建版本、数据量与测量方法。

## 固定场景
生产构建通过本地预览服务器运行；使用独立浏览器配置无扩展。测试数据 200 条完成训练、每条 10 动作×3 组，50 计划、200 动作、730 体重条目，JSON 仍需 ≤2 MiB。测试数据生成器由实现者在测试目录创建，不混入正式 seed。

## 预算
- 常规点击/勾选到可见反馈：桌面基准机连续 20 次测试，p95 ≤200ms；记录测量方法，避免把动画时长当响应时长。
- Dashboard / Progress 在已有本地数据下进入页面到主要数据可见：20 次样本 p95 ≤1s；去除首个冷加载单独记录。
- 生产首屏：本机 Lighthouse 移动预设连续 3 次，报告中位数；Performance ≥85、Accessibility 自动评分 ≥95，不能代替手工检查。
- 脚本压缩后首屏 JS 目标 ≤300 KiB（gzip），超过时必须有具体依赖分析与调整；本次 final gate 视为需解决的预算问题。
- 一场 30 分钟测试训练中不因每秒 tick 重渲染整个动作树；监听器和计时器在卸载时清理。

若运行环境不允许 Lighthouse，则此项 BLOCKED，保留同等测量候选但不自动视为通过。网络本地预览结果不外推真实公网加载体验。页面发布后需要另测真实部署。

## 兼容检查
Chromium 与至少一个第二浏览器引擎跑主要闭环、下载、文件输入、storage 事件和互斥降级。移动模拟记录清楚；真实设备未测则写明。离线刷新、PWA 安装与跨设备同步不在 P0，不能暗示已支持。
